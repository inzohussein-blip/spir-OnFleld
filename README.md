# بالملعب ⚽

منصة عربية لحجز ساحات كرة القدم (خماسي / سباعي / أي عدد)، وتنظيم المباريات، وتجهيز الفرق، وتقييم اللاعبين.

- 📱 **تطبيق اللاعبين** (`apps/mobile`): أندرويد + ويب آب (PWA) للآيفون — كود واحد بـ Expo.
- 🗄️ **الخلفية** (`supabase/`): PostgreSQL + مصادقة OTP + صلاحيات RLS.
- 📄 [خطة المشروع الكاملة](docs/PLAN.md)

## تنزيل تطبيق الأندرويد (APK)

ما يُبنى تلقائياً مع كل تحديث — يُبنى بس لما ينطلب:

- **تشغيل يدوي:** تبويب **Actions** ← **Android APK** ← **Run workflow** واختار الفرع.
- **أو وسم إصدار:** وسم مثل `v0.2.0` يبني وينشر بتبويب Releases.

بعد ما يخلص البناء:
1. افتح تبويب **Actions** ← **Android APK** ← آخر تشغيل ناجح.
2. نزّل **balmalaab-android** من أسفل الصفحة (ملف zip فيه الـ APK).
3. انقله للهاتف وثبّته (اسمح بالتثبيت من مصادر غير معروفة).

### التحديث من داخل التطبيق («حسابي ← حول»)

صفحة «حول» تفحص تلقائياً إذا أكو نسخة أحدث وتعرض زر **«حدّث للنسخة …»**:

- **الأندرويد:** يقارن رقم النسخة المثبّتة بآخر إصدار منشور بتبويب **Releases** فيه ملف APK. زر التحديث ينزّل الملف، والهاتف يثبّته فوق القديم وتبقى البيانات.
- **الآيفون (ويب):** يقارن رقم البناء بملف `version.json` المنشور ويّا الموقع، وزر «حدّث هسه» يفتح النسخة الجديدة.

حتى تنشر نسخة أندرويد جديدة يشوفها الكل بالتطبيق:
1. غيّر `version` في `apps/mobile/app.json` (مثلاً `0.2.0`). رقم البناء للأندرويد (versionCode) ينحسب منه تلقائياً.
2. شغّل **Actions ← Android APK ← Run workflow** وأشّر **«انشر كإصدار»** (ينسوّى الوسم `v0.2.0` تلقائياً)، أو سوّي الوسم بنفسك. البناء يرفض إذا الوسم ما يطابق الرقم.
3. الإصدار ينشر بتبويب Releases ويّا ملاحظات التغييرات، والتطبيق يعرضها تحت «شنو الجديد».

ملاحظة: النسخ اللي بُنيت يدوياً (Run workflow) ما تنشر بـ Releases، فما تظهر كتحديث.

## نسخة الآيفون (ويب آب)

1. في إعدادات المستودع: **Settings ← Pages ← Source: GitHub Actions** (مرة واحدة).
2. بعد كل دمج في الفرع الرئيسي (أو تشغيل **Actions ← Web App (PWA) ← Run workflow**) يُنشر التطبيق على `https://<اسم-المستخدم>.github.io/spir-OnFleld/`.
3. على الآيفون: افتح الرابط في Safari ← زر المشاركة ← **إضافة إلى الشاشة الرئيسية**.

## الوضع التجريبي وربط Supabase

بدون إعداد، يعمل التطبيق **بوضع تجريبي** ببيانات وهمية على الجهاز (رمز الدخول: `1234`).

للربط بقاعدة بيانات حقيقية:

> **الدليل الكامل خطوة بخطوة:** [docs/supabase-setup.md](docs/supabase-setup.md)

1. أنشئ مشروعاً على [supabase.com](https://supabase.com) ونفّذ الملف `supabase/setup.sql` (كل الجداول بملف واحد) بـ SQL Editor.
2. فعّل الدخول برقم الهاتف (Authentication ← Providers ← Phone) واربطه بمزوّد SMS.
3. أضف في **Settings ← Secrets and variables ← Actions**:
   - `EXPO_PUBLIC_SUPABASE_URL`
   - `EXPO_PUBLIC_SUPABASE_ANON_KEY`

## لوحة التحكم (للإدارة)

إنشاء المباريات صار من لوحة التحكم فقط، وهي تنفتح بالمتصفح على `/admin`. مثلاً: `https://<اسم-المستخدم>.github.io/spir-OnFleld/admin`.

- **مباراة جديدة:** تختار الملعب، واليوم، والساعة (الساعات المحجوزة تبين معطّلة)، والمدة، والعدد، والمستوى، وموعد فتح التسجيل.
- **اقتراحات اللاعبين:** اللاعبين يقترحون مباريات من «حسابي ← اقترح مباراة». تحوّل الاقتراح لمباراة بضغطة، وصاحبه يوصله إشعار.
- **الملاعب والصور والمواقع:** ترفع صورة لكل ملعب، وتحدد مكانه على الخريطة (تضغط على المكان أو تسحب الدبوس). الملعب اللي ما محدد مكانه ما يطلع بتبويب الخريطة.

- **طلبات حذف الحساب:** اللاعب يطلب الحذف من «حسابي» ويطلع من حسابه. الطلب يبين هنا ويّا الأيام الباقية، وينحذف الحساب خلال 30 يوم. إذا اللاعب رجع دخل لحسابه قبلها، الطلب ينلغي تلقائياً. للحذف التلقائي بعد 30 يوم بدون تدخل، فعّل pg_cron بـ Supabase:
  ```sql
  select cron.schedule('account-deletions', '17 3 * * *', 'select process_due_account_deletions()');
  ```

لتعيين مدير بقاعدة البيانات الحقيقية:
```sql
update profiles set role = 'admin' where id = '<معرّف المستخدم>';
```
بالوضع التجريبي اللوحة مفتوحة للتجربة.

## الإشعارات

**الإشعارات المحلية تشتغل فوراً بدون أي إعداد:**
- تذكير قبل المباراة بساعتين، لكل مباراة ينضم لها اللاعب.
- «ذكّرني عند فتح التسجيل» للمباريات اللي تسجيلها ما فتح بعد.

**إشعارات الخادم** تنكتب بقاعدة البيانات (`0013_push_staff.sql`) وتطلع داخل التطبيق دائماً:

| الإشعار | منو يوصله | متى |
|---|---|---|
| انفتح التسجيل 🔔 | اللي ضغطوا «ذكّرني عند فتح التسجيل» | أول دقيقة بعد فتح التسجيل |
| باقي مكان واحد ⏳ | المتابعين، وطالبي تنبيه التسجيل، وأصحاب اليوم المفضل بنفس المدينة (إذا مو منضمين) | لما ينضم لاعب ويبقى مكان واحد (مرة وحدة) |
| مباراتك بعد ساعة ⚽ | المنضمين | قبل المباراة بساعة |
| انلغت المباراة ❌ | المنضمين وقائمة الانتظار | لما الموظف أو المدير يلغيها |

«انفتح التسجيل» و«بعد ساعة» تشغّلها مهمة دورية كل دقيقة (`pg_cron` ← `run_notification_jobs()`). فعّل **pg_cron** من Database ← Extensions قبل تطبيق الملف.

**حتى توصل للهاتف وهو مسكّر (Firebase، بدون حساب EAS):**
1. سوّي مشروع Firebase، وضيف تطبيق أندرويد باسم الحزمة `com.balmalaab.app`.
2. نزّل `google-services.json` وحط محتواه بسر المستودع **`GOOGLE_SERVICES_JSON`** (Settings ← Secrets ← Actions). البناء يكتبه تلقائياً.
3. من Firebase ← Project settings ← Service accounts ← **Generate new private key**، وبعدين:
   ```
   supabase functions deploy send-push --no-verify-jwt
   supabase secrets set WEBHOOK_SECRET=<قيمة عشوائية طويلة> FCM_SERVICE_ACCOUNT="$(cat service-account.json)"
   ```
4. Database ← Webhooks ← جديد: الجدول `notifications`، الحدث INSERT، الدالة `send-push`، وHeader باسم `x-webhook-secret` بنفس القيمة.

إذا التطبيق مربوط بمشروع EAS (`extra.eas.projectId`) يستخدم رموز Expo بدل Firebase، والدالة تدعم الاثنين.

## لوحة الموظفين

الموظف (`staff`) يدير المباريات بس: ينشئ مباراة، يشوف كل المباريات الجاية والامتلاء، يلغي (واللاعبين ينبلّغون)، يقسّم الفريقين، يسجّل النتيجة، ويسكّر المباراة. ما يشوف الأرباح ولا الإعلانات ولا الإعدادات ولا طلبات الحذف.
- **التعيين:** المدير ← لوحة التحكم ← الموظفين ← رقم اللاعب (ID).
- **الدخول:** الموظف يلكى «لوحة الموظفين» بـ«حسابي»، وتشتغل بالهاتف والمتصفح.

## الخريطة

تبويب «الخريطة» يبيّن كل الملاعب المسجّلة: دبوس باسم كل ملعب، وبطاقات تحت بيها عدد المباريات القادمة، وزر «التفاصيل» وزر «الاتجاهات» (خرائط آبل على الآيفون، وخرائط كوكل بغيره). زر «موقعي» يرتّب الملاعب حسب الأقرب ويبيّن المسافة.

- المكتبة: MapLibre GL JS 6.18 مع بلاط [OpenFreeMap](https://openfreemap.org) — مجاني، بدون مفتاح، ويسمح بالاستخدام التجاري. الفكرة مأخوذة من خرائط spir-medical.
- أسماء الشوارع تطلع بالعربي وموصولة بإضافة `mapbox-gl-rtl-text`.
- نفس صفحة الخريطة تشتغل داخل WebView على الهاتف وداخل iframe على المتصفح (`src/lib/mapHtml.ts`).
- الخريطة تحتاج إنترنت: المكتبة تنحمّل من jsDelivr والبلاط من OpenFreeMap.

## فريقي

من «حسابي ← البيانات الشخصية ← فريقي» (تحت «الإحصائيات»). كل لاعب عنده رقم (ID) يطلع تحت اسمه بصفحة «حسابي»، ويكدر ينسخه ويدزّه لأصدقائه.

- **البحث:** تكتب الـ ID وتطلع بطاقة اللاعب، وبيها زر «أضفه لـ«الفريق»» لكل فريق إنت قائده.
- **طلبات الانضمام للفريق:** اللاعب يوصله الطلب (ويّا إشعار) ويوافق أو يرفض.
- **الحد:** اللاعب يكدر يكون بـ 5 فرق كحد أقصى (22 لاعب بالفريق).
- **مباريات الفريق (للقائد بس):** «اطلب مباراة للفريق كامل» يوصل للوحة التحكم كطلب فريق، ولما الإدارة تنزّل المباراة كل الفريق ينضاف لها تلقائياً. و«انضم لمباراة ويّا الفريق كامل» يبيّن المباريات اللي بيها مكان يكفي الفريق ويدخّلهم كلهم سوا.
- **الدفع:** القائد يأكّد إنه يتحمّل مبلغ أي لاعب من الفريق ما يحضر. ينحفظ مين القائد المسؤول بـ `match_players.paid_by`.
- قاعدة البيانات: `supabase/migrations/0007_teams.sql` (كل القواعد مفروضة بالدوال، مو بس بالتطبيق).

## مفتاح التوقيع الخاص (أندرويد)

نسخ الأندرويد تتوقّع بمفتاح «بالملعب» الخاص إذا موجود بأسرار المستودع. إذا مو موجود، تتوقّع بالمفتاح التجريبي العام ويطلع تحذير بالبناء.

**مرة وحدة:** GitHub ← Settings ← Secrets and variables ← Actions ← New repository secret:
- `ANDROID_KEYSTORE_BASE64`: محتوى ملف المفتاح بصيغة base64.
- `ANDROID_KEYSTORE_PASSWORD`: كلمة السر.

اسم المفتاح داخل الملف (alias) هو `balmalaab`.

احتفظ بنسخة من ملف المفتاح وكلمة السر بمكان آمن. إذا ضاع المفتاح، ما تكدر تنزّل تحديث يثبت فوق النسخة القديمة.

أول نسخة تنبني بالمفتاح الخاص لازم تنثبّت بعد حذف النسخة القديمة (مرة وحدة)، لأن التوقيع تغيّر.

## المكافآت والحضور

- **سكّر المباراة:** بعد ما تبدي المباراة، المنظّم أو الإدارة يأشّر منو حضر ومنو غاب، ويختار رجل المباراة من تصويت اللاعبين.
- **الغياب:** الغايب ينخصم عليه سعر اللاعب بعد الخصم. وإذا دخّله القائد ويّا الفريق، ينخصم على القائد.
- **رجل المباراة:** ياخذ المكافأة بمحفظته، ويطلع اسمه بصفحة المباراة.
- **دعوة الأصدقاء:** كل لاعب عنده رقم ورابط دعوة (`/?ref=رقمه`). الصديق الجديد يكتب الرقم بالتسجيل، أو خلال 14 يوم من صفحة «ادعُ أصدقاءك». لما الصديق يحضر أول مباراة ينحسب، وكل ما يكمل العدد تنضاف المكافأة.
- **المبالغ:** من لوحة التحكم ← المكافآت.
- **خصم الأوقات الهادئة:** يتحدد بإنشاء المباراة. قبل الساعة 5 العصر يتقترح 25% تلقائياً، والسعر بعد الخصم يطلع ببطاقة المباراة.

## الإشعارات بدون Firebase

التطبيق يفحص إشعاراته من الخادم كل دقيقة لما يكون مفتوح، وبالخلفية كل تقريباً 15 دقيقة (النظام يحدد التوقيت). الجديد يطلع كإشعار على الشاشة:
- انفتح مكان بمباراة مكتملة (زر «نبّهني إذا انفتح مكان»).
- مباراة جديدة بيوم من أيامك المفضلة (من صفحة الإشعارات).
- رجل المباراة، والمكافأة، وخصم الغياب.

إشعارات فورية حقيقية تحتاج ربط Firebase (FCM).

## محادثة المباراة، الفلاتر، والمفضلة

- **محادثة المباراة:** لكل مباراة محادثة للاعبين المنضمين والمنظّم، ويّا رسائل جاهزة مثل «منو يجيب الكرة؟».
- **فلاتر الرئيسية:** نوع المباراة، الوقت (صبح، عصر، ليل)، السعر، والمنطقة.
- **الملاعب المفضلة:** تنعلّم بنجمة، وتنحفظ على الجهاز.

## لوحة التحكم: الأرباح، الأعطال، وأصحاب الملاعب

- **الأرباح والامتلاء:** مدخول كل ملعب وكل يوم، والغياب، وخصومات العروض، وخريطة امتلاء الساعات حتى تعرف وين تحط عروض.
- **تقارير الأعطال:** أي خطأ عند لاعب يوصل ويّا نوع التلفون ورقم النسخة والصفحة. نفس الخطأ يتجمّع بسطر واحد.
- **صاحب الملعب:**
  - الإدارة تكتب رقمه (ID) بصفحة الملاعب.
  - يصير يشوف «ملاعبي» من «حسابي»، على التلفون والويب.
  - يشوف حجوزات ملعبه وأرباحه.
  - يحجب أوقات للصيانة أو للحجز من برّا التطبيق، وهذي الأوقات ما تنعرض بإنشاء المباريات.

**قاعدة البيانات:** `supabase/migrations/0010_rewards_attendance_owner.sql`. جرّبته على Postgres 16: إغلاق المباراة، الغياب على القائد، رجل المباراة، مكافأة 3 أصدقاء، تنبيه المكان، اليوم المفضل، صلاحيات المحادثة، وحجب الأوقات.

## الإعلانات (الرئيسية)

الإعلانات تطلع بالرئيسية فوق شريط الأيام، وتتبدل كل 5 ثواني، وتتسحب باليد. بكل إعلان مكتوب «إعلان» بالزاوية.

**لوحة التحكم ← الإعلانات وقوالبها:**
- **6 قوالب جاهزة:** خدمات المباراة، البطولات (ويّا عد تنازلي)، رجل المباراة، عروض الأوقات الهادئة، ادعُ أصدقاءك، ملعب شريك (ويّا صورة الملعب وتقييمه).
- **لكل إعلان:** الكلمة الصغيرة، العنوان، السطر الثاني، نص الزر ووين يودي (صفحة بالتطبيق، ملعب معيّن، أو مشاركة رابط الدعوة)، المدينة، تاريخ البداية والنهاية، الترتيب، وإيقاف أو تفعيل. ويّاها معاينة مباشرة.
- **التصميم ثابت لكل قالب،** وتتغير النصوص والأرقام والتواريخ بس.

**قاعدة البيانات:** `supabase/migrations/0009_ads.sql` يسوّي جدول `ads` بحماية: اللاعب يقرا الإعلانات الفعّالة بس، والإدارة تقرا وتكتب الكل. ويضيف الإعلانات الستة كبداية.
