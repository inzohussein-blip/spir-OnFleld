# خطة مشروع «بالملعب» ⚽

> منصة عربية لحجز ساحات كرة القدم (خماسي / سباعي / أي عدد)، وتنظيم المباريات، وتجهيز الفرق، وتقييم اللاعبين.
> المنصات المستهدفة: **تطبيق أندرويد** + **ويب آب (PWA) للآيفون** + **لوحة تحكم ويب لأصحاب الساحات**.
> لغة الواجهة: **العربية بالكامل (RTL)**.

---

## 0. ملاحظة مبدئية حول «الاستنساخ»

لن ننسخ أي كود أو تصميم أو شعار أو اسم من «ON FIELD» أو «العب ويانه». ما نفعله هو **بناء منتج مستقل** يقدّم نفس *فئة* الخدمة (حجز + مباريات مفتوحة + تقييم لاعبين)، بهوية «بالملعب» الخاصة وتجربة استخدام نصممها بأنفسنا، مع ميزات تميّزنا عنهم (انظر القسم 9).

## 1. أنواع المستخدمين (الأدوار)

| الدور | ماذا يفعل |
|------|-----------|
| **اللاعب** | يتصفح الساحات، يحجز ساعة، ينشئ مباراة أو ينضم لمباراة ناقصة، يقيّم زملاءه بعد المباراة. |
| **منظّم المباراة (الكابتن)** | لاعب أنشأ مباراة: يحدد العدد (5×5، 7×7، …)، يقبل/يرفض المنضمين، يقسّم الفريقين، يؤكد الحضور. |
| **المقيّم** | لاعب أو حكم موثوق يقيّم مستوى اللاعبين (مهارة، التزام، روح رياضية). يمكن أن يكون أي مشارك في المباراة أو مقيّماً معتمداً من الإدارة. |
| **صاحب الساحة** | يضيف ساحاته وأوقات العمل والأسعار، يدير الحجوزات، يغلق أوقات للصيانة، يرى الإيرادات. |
| **موظف الساحة** | صلاحيات محدودة من صاحب الساحة: تأكيد الوصول، استلام الدفع النقدي. |
| **مدير المنصة (Admin)** | يوثّق الساحات، يعالج البلاغات، يدير المقيّمين المعتمدين، يرى الإحصاءات العامة. |

## 2. الميزات حسب الوحدات

### 2.1 الحسابات والهوية
- تسجيل برقم الهاتف + رمز OTP (عبر SMS أو واتساب).
- ملف لاعب: الاسم، الصورة، المحافظة/المنطقة، المركز المفضّل (حارس، دفاع، وسط، هجوم)، القدم المفضلة.
- **بطاقة اللاعب**: المستوى العام، عدد المباريات، نسبة الالتزام بالحضور، متوسط التقييمات.

### 2.2 الساحات (Fields)
- قائمة الساحات + خريطة + فلترة (المسافة، السعر، نوع الأرضية، مغطاة/مكشوفة، الإنارة، المرافق).
- صفحة الساحة: صور، الحجم (خماسي/سباعي/حادي عشر)، السعر حسب الوقت (صباحي/مسائي/عطلة)، التقييمات.
- صاحب الساحة يمكنه تعريف **عدة ملاعب داخل نفس الموقع** (ساحة 1، ساحة 2…).

### 2.3 محرّك الحجز (Booking Engine)
- جدول زمني يومي/أسبوعي يعرض الفترات المتاحة.
- **منع الحجز المزدوج على مستوى قاعدة البيانات** (قيد `EXCLUDE` على النطاق الزمني — انظر القسم 5).
- حجز مؤقت (Hold) لمدة 10 دقائق ريثما يكتمل الدفع أو التأكيد، ثم يُلغى تلقائياً.
- حجز متكرر (مثلاً كل خميس الساعة 9 مساءً لمدة شهر).
- سياسة إلغاء يحددها صاحب الساحة (مجاني قبل X ساعة، وإلا يُخصم العربون).
- الدفع: نقداً في الساحة / عربون إلكتروني (ZainCash، FastPay، بطاقة Qi/Mastercard) — يُضاف تدريجياً.

### 2.4 المباريات وتجهيز الفريق (Matchmaking & Roster)
- **إنشاء مباراة**: اختيار الحجز (أو بدون حجز بعد) + صيغة المباراة (5×5، 6×6، 7×7، 8×8، أو عدد مخصص) + عدد الاحتياط + مستوى مطلوب (مبتدئ/متوسط/محترف/مفتوح) + خاصة أو عامة.
- **العدّاد الحي للأماكن**: «باقي 3 لاعبين» يتحدث فوراً (Realtime).
- **قائمة الانتظار**: إذا اكتمل العدد يدخل اللاعب قائمة الانتظار ويُرقّى تلقائياً عند انسحاب أحدهم.
- **دعوات**: رابط دعوة يُشارك على واتساب، أو دعوة أصدقاء من داخل التطبيق.
- **تقسيم الفريقين تلقائياً (Team Balancing)**: خوارزمية توزّع اللاعبين على فريقين بحيث يتقارب مجموع التقييم، مع احترام المراكز (حارس واحد لكل فريق إن وُجد). يمكن للكابتن التعديل يدوياً بالسحب والإفلات.
- **تقسيم التكلفة**: سعر الساعة ÷ عدد اللاعبين، مع تتبع من دفع ومن لم يدفع.
- **تأكيد الحضور**: تذكير قبل 24 ساعة وقبل ساعتين؛ من لا يؤكد يُنبّه، ومن يغيب دون اعتذار تنخفض نسبة التزامه.
- **دردشة المباراة**: محادثة جماعية بسيطة لكل مباراة.

### 2.5 التقييم والمقيّمون
- بعد انتهاء المباراة تُفتح نافذة تقييم لمدة 48 ساعة.
- كل لاعب يقيّم زملاءه (من 1 إلى 5) في محاور: **المهارة**، **اللعب الجماعي**، **الروح الرياضية**، + اختيار **أفضل لاعب في المباراة (MVP)**.
- **المقيّم المعتمد**: تقييمه وزنه أعلى (مثلاً ×3)، ويستطيع إعطاء تقييم تفصيلي (سرعة، تمرير، تسديد، دفاع، حراسة).
- حساب المستوى: متوسط مرجّح مع تقليل أثر التقييمات الشاذة (تجاهل أعلى/أدنى قيمة إذا كان العدد كافياً) + تخفيف تدريجي للتقييمات القديمة.
- تقييم الساحة نفسها من اللاعبين (النظافة، الأرضية، الإنارة، التعامل).
- نظام بلاغات (سلوك سيئ، عدم حضور متكرر).

### 2.6 الإشعارات
- انضمام لاعب، اكتمال العدد، تغيير الموعد، تذكير قبل المباراة، طلب تقييم، تأكيد حجز من صاحب الساحة.
- أندرويد: Firebase Cloud Messaging (FCM) عبر Expo Notifications.
- آيفون (PWA): Web Push (مدعوم في iOS 16.4+ بعد «إضافة إلى الشاشة الرئيسية»).
- بديل احتياطي: رسالة واتساب/SMS للتذكيرات المهمة.

### 2.7 لوحة تحكم صاحب الساحة (ويب)
- تقويم الحجوزات لكل ملعب، إضافة حجز يدوي (لزبون اتصل هاتفياً).
- إدارة الأسعار وأوقات العمل والإغلاقات.
- تقارير: الإيراد اليومي/الشهري، نسبة الإشغال، أكثر الأوقات طلباً.
- إدارة الموظفين وصلاحياتهم.

### 2.8 لوحة الإدارة (Admin)
- توثيق الساحات الجديدة، إدارة البلاغات، اعتماد المقيّمين، إحصاءات عامة.

## 5. قواعد العمل الحساسة (Business Rules)

1. **منع الحجز المزدوج**: قيد `EXCLUDE USING gist (field_id WITH =, during WITH &&)` على الحجوزات الفعالة فقط — قاعدة البيانات نفسها ترفض أي تداخل، حتى لو ضغط شخصان «احجز» في نفس اللحظة.
2. **الانضمام للمباراة ذرّي**: دالة `join_match()` تقفل صف المباراة (`FOR UPDATE`)، تعدّ اللاعبين، وتضيف اللاعب كـ `joined` أو `waitlist`.
3. **الترقية من الانتظار**: عند انسحاب لاعب، تُرقّى أول حالة انتظار تلقائياً ويُرسل له إشعار.
4. **التقييم مسموح فقط** لمن لعب فعلاً في نفس المباراة، مرة واحدة لكل لاعب، وخلال 48 ساعة من نهايتها، ولا يقيّم نفسه.
5. **نسبة الالتزام** = المباريات المحضورة ÷ المباريات المؤكدة؛ تُستخدم لترتيب الأولوية في المباريات المزدحمة.
6. **الصلاحيات (RLS)**: صاحب الساحة يرى حجوزات ساحاته فقط؛ اللاعب يعدّل بياناته فقط؛ التقييمات لا تظهر بأسماء المقيّمين.

### خوارزمية تقسيم الفريقين (مبسطة)
```
1. رتّب اللاعبين تنازلياً حسب skill_rating.
2. ضع الحراس أولاً: حارس لكل فريق.
3. وزّع الباقين بأسلوب «الثعبان» (A, B, B, A, A, B, ...).
4. حسّن بالتبديل: جرّب تبديل كل زوج (لاعب من A ↔ لاعب من B)
   واعتمد التبديل إذا قلّل الفرق |مجموع A − مجموع B|، حتى لا يوجد تحسين.
```

## 6. الشاشات الرئيسية (تطبيق اللاعب)

1. **البداية**: تسجيل برقم الهاتف → رمز التحقق → إكمال الملف (المركز، المنطقة).
2. **الرئيسية**: مباريات قريبة ناقصة لاعبين («باقي 2») + مبارياتي القادمة + زر «أنشئ مباراة».
3. **الساحات**: قائمة/خريطة + فلاتر.
4. **صفحة الساحة**: صور، أسعار، جدول الأوقات المتاحة، زر «احجز».
5. **إنشاء مباراة**: الصيغة (5×5، 7×7، مخصص)، المستوى، عامة/خاصة، التكلفة.
6. **صفحة المباراة**: العداد الحي، قائمة اللاعبين، الفريقين (A/B) على شكل ملعب، الدردشة، زر انضمام/انسحاب، مشاركة الدعوة.
7. **التقييم بعد المباراة**: بطاقات اللاعبين مع نجوم + اختيار MVP.
8. **ملفي**: بطاقة اللاعب، الإحصاءات، سجل المباريات، الإعدادات.

## 8. النشر

- **أندرويد (الآن)**: GitHub Actions يبني ملف APK تلقائياً مع كل تحديث (`.github/workflows/android.yml`) — بدون حساب EAS.
- **أندرويد (للنشر على المتجر)**: ملف AAB موقّع بمفتاح الإصدار → Google Play Console (حساب مطوّر ~25$ لمرة واحدة).
- **الآيفون (PWA)**: `npm run build:web` → GitHub Pages تلقائياً (`.github/workflows/web.yml`) مع `manifest.json` وأيقونة الشاشة الرئيسية؛ المستخدم يفتح الرابط في Safari ← «مشاركة» ← «إضافة إلى الشاشة الرئيسية».
- **لوحة التحكم**: Next.js على Vercel.
- **الخلفية**: Supabase (الخطة المجانية تكفي للتجربة، Pro عند الإطلاق ~25$/شهر).
- لاحقاً iOS أصلي: نفس كود Expo → EAS Build → App Store (اشتراك Apple ~99$/سنة).

## 9. ميزات تميّز «بالملعب»

1. **مؤشر الالتزام** ظاهر على بطاقة اللاعب — يقلّل مشكلة «الذي يحجز ولا يحضر».
2. **تقسيم فرق عادل تلقائي** بناءً على التقييم والمراكز.
3. **«أكمل العدد بسرعة»**: إذا نقص لاعب قبل المباراة بساعتين، يُرسل إشعار للاعبين القريبين بنفس المستوى.
4. **حجز متكرر للمجموعات الثابتة** (الشلّة الأسبوعية) مع تذكير تلقائي.
5. **مشاركة سهلة على واتساب** برابط يفتح المباراة مباشرة.
6. **دعم كامل للعربية واللهجة المحلية** في النصوص والإشعارات، والأرقام والعملة (د.ع).

## 14. توجّه الواجهة (UI/UX)

استناداً إلى تحليل واجهات التطبيقات المنافسة، اعتمدنا **البنية والميزات** دون نسخ هويتها البصرية:

- **التنقل**: شريط سفلي بخمسة أقسام: الرئيسية، الاختبارات، المنشورات، البطولات، الإحصائيات؛ والحساب والمحادثات من رأس الصفحة.
- **الرئيسية**: لافتات عروض قابلة للتمرير، قسما المباريات (ملعب كامل 11×11 / مباريات سريعة)، اختصارات (حجز سريع، البطولات، الإحصائيات، مبارياتي).
- **التلعيب (Gamification)**: بطاقة لاعب بتصميم «بالملعب» الخاص (أخضر بخطوط الملعب، فئات حسب التقييم)، تشكيلة الأسبوع على أرضية ملعب، لاعب الشهر.
- **الهوية**: الأزرق الملكي (#1E4FD8) والأبيض مع لمسات ذهبية — بدرجات وشعار وتصميم بطاقات خاص بـ«بالملعب»، خط Cairo، ووضع فاتح/داكن.
